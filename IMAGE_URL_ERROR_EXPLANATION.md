# Why `/_next/image` URL Fails

## The Problem

When you paste this URL in browser:
```
https://lightsteelblue-meerkat-493160.hostingersite.com/_next/image?url=%2Fuploads%2Fadmin-1768274017990-graphics-ts.jpg&w=640&q=75
```

You get: **"The requested resource isn't a valid image"**

## Why This Happens

This URL is generated by **Next.js Image component** when it tries to optimize images. The `/_next/image` route is Next.js's image optimization API.

**The problem:**
1. Next.js Image component sees `/uploads/file.jpg`
2. It tries to optimize it via `/_next/image?url=/uploads/file.jpg`
3. The optimization API tries to fetch the file from `public/uploads/`
4. **But in production with Nginx**, the file might be served directly by Nginx
5. Next.js optimization API can't access it → Error

## The Solution (Already Applied)

I've updated the code to use a **regular `<img>` tag** for local uploads:

```typescript
// For /uploads/ images - use regular img tag (no optimization)
slide.image.startsWith('/uploads/') ? (
  <img src={slide.image} ... />
) : (
  // For external URLs - use Next.js Image
  <Image src={slide.image} ... />
)
```

## What This Means

**Before (Broken):**
- Next.js Image → `/_next/image?url=/uploads/file.jpg` → ❌ Fails

**After (Fixed):**
- Regular img tag → `/uploads/file.jpg` → ✅ Works directly

## Why Direct URL Works But `/_next/image` Doesn't

**Direct URL:**
```
/uploads/admin-1768274017990-graphics-ts.jpg
```
✅ Nginx serves it directly from filesystem
✅ No Next.js processing needed

**Next.js Optimization URL:**
```
/_next/image?url=/uploads/file.jpg
```
❌ Next.js tries to fetch and optimize
❌ Can't access file if Nginx is serving it directly
❌ Optimization API fails

## If Direct URL Also Fails

If `https://yourdomain.com/uploads/file.jpg` also fails, the issue is:

1. **File doesn't exist:**
   ```bash
   ls -la public/uploads/admin-1768274017990-graphics-ts.jpg
   ```

2. **Nginx not configured:**
   - Check Nginx config has `location /uploads` block
   - See `PRODUCTION_IMAGE_FIX.md` for Nginx setup

3. **File permissions:**
   ```bash
   chmod 644 public/uploads/*
   ```
